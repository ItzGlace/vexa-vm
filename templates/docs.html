Introduction

Quick start

API v1

Create a scoped key in Settings → API keys. Send it as a Bearer token over HTTPS. The examples use a placeholder key; the panel never inserts a real credential into this page.

Request
curl --request GET \
  --url https://your-node.example/api/v1/host \
  --header 'Authorization: Bearer <your-api-key>' \
  --header 'Accept: application/json'

Authentication

Panel pages use an opaque server-side session cookie and CSRF protection. Automation uses API keys; public VM pages exchange a one-time URL token for a short-lived, scoped cookie. These credential types are not interchangeable.

CredentialUseTransport
API keyServer-to-server automationAuthorization: Bearer …
Admin sessionWeb panelSecure HttpOnly cookie + CSRF
Status/VNC tokenOne VM, limited actionsOne-time path token → 10 minute cookie

Virtual machines

VM creates and destructive changes return an operation. Poll the operation URL instead of repeating the request.

GET/vms

List every managed VM with networking and the latest stored metrics.

POST/vms

Create and optionally start a VM. The omitted guest administrator defaults to Administrator for Windows images and root otherwise. Requires vms:write.

GET/vms/{id}

Read configuration, networking and latest metrics.

PATCH/vms/{id}

Grow compute/storage or update metadata and limits.

DELETE/vms/{id}

Delete the domain and its managed disks. Irreversible.

Example create payload
{
  "name": "web-01",
  "hostname": "web-01.example.net",
  "iso_id": "ubuntu-24-04",
  "vcpus": 2,
  "memory_mib": 2048,
  "disk_gib": 25,
  "ip_addresses": ["203.0.113.10", "2001:db8::10"],
  "network_limit_mbps": 10000,
  "traffic_limit_bytes": null,
  "root_username": "root",
  "password": "use-a-secret-manager",
  "start": true
}

Vexa Guest Tools

The create and reinstall forms expose one opt-in checkbox for compatible automated images. Linux is injected through cloud-init; Windows images must declare the Cloudbase-Init NoCloud provisioner. Each VM receives a unique AES-encrypted channel secret, and every virtio-serial request is HMAC authenticated, timestamped and replay checked.

Live operations

Password, hostname, DNS, SSH keys, shutdown, reboot and authenticated health/version probes.

Honest fallback

If tools are not installed or connected, supported desired values are saved as pending for the next compatible reinstall; the API never reports a live change that did not happen.

Firewall, DDoS and abuse controls

All VM firewall, flood-protection and host BCP38 enforcement switches are off by default. An administrator must enable them explicitly. Enabled policy is bound to the host-owned TAP interface and applied atomically with nftables; host BCP38 also pins the configured Ethernet source MAC, and a protected VM fails closed if its policy cannot be installed.

  • • VM rules and flood thresholds: /vms/{id}/network-security and /vms/{id}/firewall/rules.
  • • Host-only, optional BCP38 source filtering: /network/security. Customer tokens cannot access it.
  • • Provider IP holds and evidence: /network/blacklist and /network/abuse-records.
  • • A status link receives firewall access only when the admin grants it, and may then create only customer-owned inbound TCP/UDP port-drop rules.

Signed updates

The updater is pinned to ItzGlace/vexa-vm. It accepts only a published manifest whose exact bytes verify against a root-owned Ed25519 trust store. Components start unselected; approval is bound to the release, manifest digest, component set, super-admin session and a 15-minute window.

MethodEndpointPurpose
GET/updatesRead trust/executor and staged state
POST/updates/checkFetch and verify signed release metadata
POST/updates/stageDownload and rehash the bounded Vexa archive
POST/updates/approveSuper-admin-only activation approval

QEMU/libvirt remain distribution packages and are restricted to signed-manifest package/version allowlists. The privileged executor uses a versioned application layout, SQLite backup, health checks and automatic application rollback.

Customer access

Create status or VNC links through the admin API. Public calls are under /api/public and are authorized only by the exchanged cookie. A response is scoped to one VM and cannot change CPU, RAM, disk, traffic allowance, port speed or IP ownership. Firewall access is omitted by default and appears only when the admin grants the dedicated scopes.

POST /vms/{id}/status-tokens

Generate a scoped, individually revocable customer link.

POST /vms/{id}/vnc-tokens

Generate a one-time, 10-minute console link.

GET /api/public/vm

Return the single scoped VM after token exchange.

Operations and audit logs

Long-running mutations return 202 Accepted with an operation. Poll until status is succeeded, failed or cancelled. Requested and completed VM actions are append-only audit records with actor IDs; API request records add the trusted source IP, user agent, request ID and outcome. Provider abuse evidence has its own IPv4/IPv6 record endpoints.

  "operation": {
    "id": "op_01J…",
    "kind": "vm.create",

    "progress_percent": 35,
    "vm_id": "vm_01J…"
  }
}

{

    "code": "conflict",
    "message": "conflict: the selected IP address is already assigned",
    "request_id": "req_01J…"
  }
}
